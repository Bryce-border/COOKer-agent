> 依据：2026-10-30 实际读取的仓库文件；2026-10-31 按麦当劳技能重新接入更新（旧版工作台已归档到分支 `archive/mcd-v1`）（`README.md`、`pyproject.toml`、`langgraph.json`、`config/models.yaml`、`src/**`、`web/src/**`、`scripts/**`、`tests/**`、`docs/**`）。
> 标注约定：**事实**=代码/配置可直接确认；**推断**=由结构推测，未在代码中写死。

## 0. 项目是什么

- 本地部署的个人做饭 Agent，数据源是上游 `HowToCook/` 仓库克隆（372 道菜左右的快照）。**事实**（README 第 3 行）
- 三种入口：Web 聊天（Next.js，3000 端口）、终端聊天 `cooker-chat`、MCP Server `cooker-mcp`。
- 可选技能：麦当劳管家（`skills/mclottery-alchemist/` + `src/cooker/mcd/`），聊到麦当劳时才加载；写操作在对话内确认卡完成，只在本机单账户使用。
- 不是完全离线：聊天、结构化抽取、向量化、重排都调云端 API（百炼）。

关键约束（来自代码与配置）：

| 约束 | 位置 |
|---|---|
| Python 必须 3.12 | `pyproject.toml` `requires-python` |
| 图名必须是 `cooker` | `langgraph.json` 的 `graphs.cooker` |
| 前端固定 3000、后端固定 2024 | `README.md`、`web/.env` |
| 模型 ID 不写在代码里，只在 YAML | `config/models.yaml`（代码按「角色」取模型） |

## 3. 后端 `src/cooker/`（项目核心）

### 3.1 装配与业务出口

| 文件 | 作用 |
|---|---|
| `settings.py` | `Settings`：路径（数据目录、HowToCook 目录、config 路径）来自环境变量/.env；`get_settings()` 单例 |
| `service.py` | `CookerService`：把 store / retriever / 领域函数组合成对外的精简模型（`RecipeSummary`、`SearchResult`、`RecipeDetail`、`TipResult`）。MCP、Agent、HTTP 三个入口都调它，不各自拼底层。`get_service()` 懒加载单例，索引缺失时 `retriever=None` 并降级 |
| `api.py` | 挂到 LangGraph Server 的自定义 Starlette 路由：`GET /cooker/recipes?name=`、`GET /cooker/images/{path}`。路由写成同步 `def`（阻塞 IO 走线程池，避免阻塞流式输出）；`resolve_image()` 做路径穿越防护 |

### 3.2 `agent/`：对话编排（学习优先级最高）

| 文件 | 作用 |
|---|---|
| `graph.py` | 图定义（状态 `AgentState` = 消息 + 已加载技能 `skills`）。`START → agent →(有 tool_calls) tools → agent`；`agent →(无 tool_calls) verify → END`，校验不通过回 `agent` 重答，最多 `MAX_CORRECTIONS=2` 次。`call_model`：读档案→`trim_messages`(12k token, `start_on="human"`)→调模型；`get_agent_model(provider, require_tool, skills)` 用 `lru_cache` + `transform` 分别给主备模型 `bind_tools`（已加载技能的工具才绑定），重答时用 `tool_choice="required"` 强制调工具。`graph = build_graph()` 供 Server 加载 |
| `tools.py` | 9 个菜谱/档案工具（`search_recipes`、`get_recipe`、`recommend_by_ingredients`、`browse_recipes`、`scale_recipe`、`make_shopping_list`、`search_cooking_tips`、`update_profile`、`get_profile`）。`_filter()` 把用户档案里的过敏原/忌口转成检索过滤条件；`update_profile` 里用 `interrupt()` 做「移除过敏原需确认」 |
| `prompts.py` | `build_system_prompt(profile, skills)`：每轮动态注入档案与技能索引；已加载技能时附上 SKILL.md 正文 + 宿主适配 |
| `profile.py` | 长期记忆：`UserProfile` 模型 + 在 LangGraph `Store` 上按 `namespace` 读写（跨会话、跨进程） |
| `verify.py` | **确定性**回答校验（不调 LLM）：解析最终回答里引用的菜名，检查是否有本轮工具结果支撑（本轮调过麦当劳工具时跳过无括号菜名扫描）；`correction_message()` 生成反馈消息，`is_correction()` 识别校验反馈 |
| `cli.py` | 终端入口 `cooker-chat`：SQLite checkpointer + Store，`ask()` 处理过敏原确认与麦当劳确认卡，`/new`、`/profile`、`/provider`、`/quit`，`--thread` 续聊 |

### 3.3 `ingest/`：离线入库（把 Markdown 变成结构化数据）

| 文件 | 作用 |
|---|---|
| `parser.py` | 规则解析 HowToCook Markdown：按 H2 切段、抓步骤/用量/图片，`content_hash()` 算内容哈希，格式不符抛 `RecipeFormatError`，遍历 `iter_recipe_files` / `iter_tip_files` |
| `schema.py` | 数据模型：`ParsedRecipe`/`ParsedTip`（解析层）→ `Recipe`/`RecipeFacts`/`Ingredient`/`StepGroup`（存储层）；标签归一化、单位归一化、无量词默认「适量」 |
| `allergens.py` | `derive_allergens()`：关键词词典推导过敏原，纯规则，不调 LLM |
| `extractor.py` | LLM 结构化抽取：把原文抽成 `RecipeFacts`（用量、口味、耗时、主料等），带**内容哈希 + Prompt 版本**缓存（`FactsCache`），`extract_all` 批量并发 |
| `pipeline.py` | 入口 `cooker-ingest`：解析全部菜谱 → 增量抽取 → 写 `data/recipes.json`、`data/tips.json`、`data/ingest_report.json`。`--limit`/`--only`/`--no-llm` 是调试开关 |

### 3.4 `retrieval/`：检索（RAG 主体）

| 文件 | 作用 |
|---|---|
| `chunks.py` | 切块：菜谱按「概览 / 操作分组 / 附加」切，技巧按标题切；`Chunk` 带标题头，避免上下文丢失 |
| `indexer.py` | 入口 `cooker-index`：切块 → 向量化（按文本哈希增量缓存 `EmbeddingCache`）→ 写 `data/index/chunks.json`、`vectors.npy`、`meta.json` |
| `retriever.py` | `HybridRetriever`：jieba 分词 → BM25 + 向量召回 → **RRF 融合** → 按文档聚合 → 重排。含 `CircuitBreaker`（向量/重排失败时降级并熔断）、`Evidence`/`Hit` 数据结构 |

### 3.5 `recipes/`：领域计算（确定性，无 LLM）

| 文件 | 作用 |
|---|---|
| `store.py` | `RecipeStore`：加载 `recipes.json`/`tips.json` 到内存，按 ID/别名查找、`RecipeFilter` 结构化过滤、`get_store()` 单例 |
| `ingredients.py` | 食材名归一化与匹配（别名、主料判断、菜名 key），推荐与购物清单都依赖 |
| `recommend.py` | 按现有食材推荐：基于 `main_ingredients` 覆盖度打分 + 多样性打散，**不走向量检索** |
| `scaling.py` | 按人数换算用量、合并购物清单（同名同单位合并、取整规则） |

### 3.6 `llm/`：模型接入层

| 文件 | 作用 |
|---|---|
| `factory.py` | 核心适配层：读 `models.yaml` → `load_models_config()` → `resolve_provider()` → `build_runnable(role)`。屏蔽 `langchain-qwq` / `langchain-deepseek` 差异；主备 provider 降级；`enable_thinking` 开关；密钥只用环境变量 |
| `embedding.py` | `Embedder` / `Reranker` 客户端（百炼），`get_embedder()` / `get_reranker()` 单例；批量上限、超时、重排端点为非标准路径 |

### 3.7 `mcp_server/`

| 文件 | 作用 |
|---|---|
| `server.py` | 入口 `cooker-mcp`：FastMCP 暴露 7 个菜谱工具（不含档案读写和过敏原确认），`--http` 可起 8765 |

### 3.8 `skills.py` 与 `mcd/`：技能按需加载 + 麦当劳 MCP

| 文件 | 作用 |
|---|---|
| `skills.py` | 扫描 `skills/*/SKILL.md`：`index_prompt()` 索引、`active_prompt()` 正文、`load_skill`（`Command` 更新状态 `skills`）、`read_skill_file`（只能读 references 白名单） |
| `mcd/config.py` | `McdSettings`：读 `mcd-mcp.local.env`，只允许官方端点，去掉 Bearer 前缀 |
| `mcd/client.py` | `call()`：每次独立 MCP 会话 → 线上结构 jsonschema 校验 → 调用 → 解析 → Token 替换；读写白名单；`McdError` / `McdUnknown`；`for_model()` 分→元换算与截断 |
| `mcd/tool_schemas.json` | 官方 36 个工具的结构快照（`scripts/sync_mcd_tools.py` 生成） |
| `mcd/tools.py` | 快照 → `StructuredTool`（JSON Schema 作 args_schema，同步 / 异步双入口，未加载技能时拒绝） |
| `mcd/actions.py` | 7 个写工具：实时查询建确认卡 → `interrupt` → 指纹比对 → 台账认领 → 执行一次 → 结算 |
| `mcd/ledger.py` | SQLite 台账 `data/mcd-ledger.sqlite3`：tool_call_id 幂等、`BEGIN IMMEDIATE` 认领、UNKNOWN 冻结；`python -m cooker.mcd.ledger list/resolve` 人工解冻 |
| `mcd/host_adapter.md` | 技能在 COOKer 中的适配说明（工具改名、无工作台、确认卡、【】只给菜名） |

逐步实现讲解见 `learning/02-麦当劳技能接入-逐步实现.md`。

## 11. 建议阅读顺序（后续专题按此推进）

1. **入口链路**：`langgraph.json` → `agent/graph.py` → `agent/tools.py` → `service.py`（一轮对话怎么跑完）。
2. **检索链路**：`ingest/parser.py` → `extractor.py` → `retrieval/chunks.py` → `indexer.py` → `retriever.py`（结构化 + 混合检索为什么这么做）。
3. **记忆与校验**：`profile.py` → `prompts.py` → `verify.py` → `tools.py:update_profile`（跨会话记忆与确定性校验）。
4. **模型接入**：`llm/factory.py` + `config/models.yaml`（角色化配置、主备降级）。
5. **前端一条链路**：`app/page.tsx` → `providers/Stream.tsx` → `thread/index.tsx` → `lib/cooker.ts` → `components/cooker/recipe-sheet.tsx`。
6. **技能与麦当劳**（可选）：`skills.py` → `agent/graph.py`（AgentState.skills）→ `mcd/tools.py` → `mcd/actions.py` → `mcd/ledger.py`；配合 `learning/02-麦当劳技能接入-逐步实现.md`。

> 待确认：优先从「一轮对话链路」还是「检索链路」开始。
